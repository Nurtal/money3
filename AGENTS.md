Benchmark results serialize to JSON and `detect_regressions` flags F1↓>2%, recall↓>3%, latency↑>20% (README thresholds).
- **Search & API (Phase 6) is scaffolded**: `api.py` is a FastAPI app (`create_app(db_url)`) with `GET /api/aaps` (full-text `q` + filters: organisation/status/topic/deadline_before/amount_min), `GET /api/aaps/{id}`, `GET /api/aaps/{id}/similar` (Jaccard over topics+org), `GET /api/sources`, and a minimal web UI at `/` (OpenAPI docs auto-served at `/docs`). Requires the `api` extra (`fastapi`, `uvicorn`); run with `aap-watcher serve --db …`.

- Python tooling is real and verified: `uv` + `pyproject.toml`, `src/` layout, `pytest`. ## Developer commands (verified)

- Install: `uv venv && uv pip install -e ".[test]"`
- Run tests: `uv run pytest` (offline fixtures; no network needed)
- CLI: `uv run aap-watcher --db sqlite:///aap_watcher.db` (live scrape; respects robots.txt and will skip if unreachable)
- Benchmark: `uv run aap-watcher benchmark [--corpus data/benchmark/gold/v1.jsonl] [--split {train,val,test,all}] [--field-matrix] [--save results.json]` — runs extractors over the gold corpus and prints measured F1/precision/recall, latency, cost; `--field-matrix` adds a per-extractor × per-field F1 table. **spaCy NER is real** (`fr_core_news_md`, needs the `spacy` extra; install the model via `uv run python -m spacy download fr_core_news_md`). **PDF parsing is real** (`scrapers/pdf_parser.py`, needs the `pdf` extra / pypdf, auto-detected in `BaseScraper.fetch`).
- Monitor: `uv run aap-watcher monitor --db sqlite:///aap_watcher.db` — one pass over all sources, reporting new/modified/deadline-changed/cancelled (run from cron for scheduled monitoring)
- Regression: `uv run aap-watcher regression --before a.json --after b.json` — flags benchmark regressions per README thresholds
- Serve: `uv run aap-watcher serve --db sqlite:///aap_watcher.db [--host 127.0.0.1 --port 8000]` — FastAPI REST API + web UI (needs the `api` extra)
- New extractors/sources must remain runnable under `uv run pytest` with offline fixtures.

## Core principle: benchmark-first, not LLM-first

- Extraction is framed as a **benchmark over competing strategies** (regex, dictionaries, classical NLP, spaCy, BERT/CamemBERT, LLM, hybrid). No extraction technology is "the winner" before it is benchmarked.
- **Do not rewrite the pipeline to rely on an LLM** by default. Use LLMs only where they show a measurable advantage over simpler approaches.
- Every extracted value should be **traceable to its source** (source text/url, method, model + prompt version, timestamp). Preserve provenance in schemas and outputs.

## Adding extractors or sources (workflow constraints)

- New **extractors** must implement the shared `Extractor` interface (`extract(document) -> AAPExtraction`) so all strategies get identical inputs and comparable outputs.
- New **sources** are added as independent source adapters under `scrapers/`; add fixtures, tests, and documentation for each.
- **Never modify the canonical AAP schema or the benchmark protocol** without an explicit Architectural Decision Record (ADR). Significant choices go through `docs/architecture/adr/`.
- Do **not commit hand-estimated benchmark scores**. Actual results must be generated by running the benchmark; illustrative numbers in the README are examples only.

## Operational gotchas

- Scraper must be **polite**: respect `robots.txt`, honour site ToS, rate-limit (README example: 0.5 req/s), cache downloads, use a descriptive User-Agent, never bypass auth or technical restrictions.
- The AAP lifecycle and schema are defined in the README (fields table, statuses: upcoming/open/closing_soon/closed/cancelled/archived). Reuse these exact names when implementing.
- AAP Watcher is **not an authoritative source** for funding decisions; extracted data must carry a disclaimer and link back to the official source.
